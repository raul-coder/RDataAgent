## 1.4 意图识别

`agent/nodes/intent.py:56 classify()` 按**短路顺序**匹配，规则优先、零延迟、可预测：

```
chitchat(:63) → out_of_scope(:70) → result_ops(:77) →
compare(:81) → attribution(:83) → warning(:85) →
proportion(:87) → trend(:89) → ranking(:91) → data_query(:94 兜底)
```

`result_ops` 四类操作（`OPS_PATTERNS:16-21`）：`sort` / `chart` / `export` / `topn`。

判定后由 `runtime.py` 三分支分流：

| 分支 | 触发条件 | 行为 |
| --- | --- | --- |
| 模板回复 | `chitchat` / `out_of_scope` | 直接推文案，不查库 |
| 结果二次加工 | `result_ops` | 用 Redis 缓存的上轮结果集做纯 Python 变换 |
| 完整流水线 | 其余 | 走完 5 步取数链路 |

## 1.5 SQL 生成的 Prompt 组装

`agent/nodes/sql_generate.py:70-99`，`user_parts` 拼接顺序：

```
[0] # 当前问题\n{rewritten}
[1] {slot_hint}          ← 【继承的上文分析条件】
[2] {schema.render()}    ← 数据源 / 指标 / 维度 / 强制业务规则 / 别名约定
[3] 【参考示例】          ← _pick_fewshots top-3（score > 0.05）
[4] 【最近对话】\n{history}
[5] 【上一轮 SQL（供多轮追问参考）】\n{prev_sql}
[6] 【上一次执行失败，请修正】\n{retry_hint}   ← 仅自愈重试时
```

最终 `messages = [system=SYSTEM_PROMPT, user="\n".join(user_parts)]`。

## 1.6 追问（多轮）机制

### 1.6.1 槽位存在哪

**不在数据库，在 Redis 的会话上下文** `ctx.active_slots`（`runtime.py:97` 读 / `:332-349` 写）。结构定义见 `agent/slots.py:15`：

```python
metrics / dimensions / filters / time_range / compare / order / limit / subject / chart_hint
```

### 1.6.2 继承算法

`agent/slots.py:54 merge(prev, cur)`：

```python
out.metrics     = cur.metrics or prev.metrics       # 本轮命中覆盖，未命中继承
out.dimensions  = cur.dimensions or prev.dimensions
out.time_range  = cur.time_range or prev.time_range
out.limit       = cur.limit if cur.limit is not None else prev.limit
out.filters     = 按 dim 去重覆盖（同一维度新替旧）   # 实现「条件叠加」
```

### 1.6.3 rewrite 的三条分支

`agent/nodes/rewrite.py:271-286`：

| 分支 | 触发 | 行为 |
| --- | --- | --- |
| ① 续问 | `is_continuation(question)`（含「那 / 它 / 其他 / 呢 / 换成」等标记，见 `rewrite.py:23`） | `build_question(merged)` 把槽位展开成完整问句，如「那北京呢」→「2026年 北京代表处 商业收入」 |
| ② 自足问题 | 本轮含指标或维度 | 原样使用，继承条件以「（继承：…）」附在后面 |
| ③ 条件叠加 | 本轮只有筛选 / 修饰 | `_inherited_hint` 补全继承条件后附加 |

### 1.6.4 实例：「拆到产品线看看」

```
命中分支③
→ extract_slots 抽出 dimensions=["product_line"]
→ merge 继承上轮 time_range{last_months:3} 与 metrics=["biz_income"]
→ rewritten = "拆到产品线看看（继承：3，商业收入）"
→ 以 slot_hint 注入 Prompt，让 LLM 把时间条件写进 WHERE
```

> **排障要点**：槽位抽取发生在 `runtime.py:178`，即 step1 之后、step2 生成 SQL 之前。
> 曾出现「最近 **3 个**月」的 3 被误抽成 `limit`，SQL 因此拼上 `LIMIT 3` 截断分组结果，
> 导致「总收入」与「拆维度后合计」两个数字对不上。修复见 `rewrite.py` 的 `TIME_SPAN_RE`。

### 1.6.5 result_ops 分支 vs 完整流水线

| 维度 | result_ops | 完整流水线 |
| --- | --- | --- |
| 触发 | `intent.classify` 命中 OPS_PATTERNS | 其余 |
| 是否跑 SQL | **否**，用 Redis 缓存的上轮结果集 | 是 |
| 是否调 LLM | 否（纯 Python 变换） | 是 |
| 是否更新槽位 | **否**（`runtime.py:159` 只 `ctx_store.save(ctx)`） | 是（`:332-349`） |
| 响应耗时 | 毫秒级 | 秒级 |
| 前端触发点 | `ResultToolbar.tsx:19-60`（降序 / 升序 / 换图 / 导出）→ `doAsk('按降序排序')` 等 | 输入框 / 快捷提问 / 追问 chip / 重新生成 |

`result_ops.apply(payload, op, question)`（`result_ops.py:47-103`）：

- **`sort`（:59-72）**：`_numeric_columns` 找全数值列 → `_match_column` 看问题是否点名某列 → 未点名取最后一个数值列 → 按 `SORT_ASC` 判方向 → 排序后**重新跑 `chart_advisor.advise`**
- **`chart`（:74-85）**：按 `CHART_KEYWORDS` 定目标类型；`table` 直接返回；其余交给 `advise(..., hint=...)`
- **`topn`（:87-97）**：`TOPN_PATTERNS` 取 N（默认 10），`rows[:N]` 并同步更新 `total`
- **`export`（:99-101）**：只回一句文案。**真正的导出是纯前端** `index.tsx:20-37 exportCsv`，用当前结果集生成带 UTF-8 BOM 的 CSV

## 1.7 实现与直觉不符之处

以下 7 项均为源码走查确认，排障时容易被误导，建议保留在文档中：

| # | 现象 | 位置 |
| --- | --- | --- |

## 3.1 初始化与运行期是彻底分离的

服务启动时对数据库和 LLM **不做任何探活**（DB 仅 `pool_pre_ping`，LLM 完全不校验），所有 schema 与种子数据靠 `Makefile` 编排的手动脚本。

## 4.5 后端 `_build_history` —— 对话窗口

```python
def _build_history(messages) -> str:
    # 只取最近 MAX_HISTORY_TURNS*2 = 12 条（6 轮），更早的丢弃以控制 Prompt 体积
    messages = messages[-MAX_HISTORY_TURNS * 2:]
    lines = []
    for m in messages:
        role = "用户" if m.role == "user" else "助手"
        content = (m.content or "").replace("\n", " ")[:200]   # ← 换行压平 + 截断 200 字
        lines.append(f"{role}：{content}")
    return "\n".join(lines)
```

**注意**：用的是原始 `content`，**不含 SQL 与表格数据**。助手侧是流式拼接后的完整结论文本。

> **★ `TIME_SPAN_RE` 的由来（2026-08-30 修复）**
> 原实现直接用 `r"(\d+)\s*个"` 匹配条数，导致「最近 **3 个**月」的 3 被当成返回条数，

>     re.compile(r"(?:TOP|top)\s*(\d+)"),
>     re.compile(r"前\s*(\d+)\s*(?:个|名|条)?"),
