## 1. Provider 超时 + 熔断（P0）

**为什么记下来**：降级链理论上存在，实际不可用。

**证据**（2026-09-02 冒烟复现）：云端模型配额耗尽后，4 个 Provider **串行**各等 60–90s 才失败，
整次请求 **200s 仍未落到检索式兜底**，客户端已超时放弃。

日志佐证——相邻两次「模型调用失败」间隔约 90s：

```
14:57:41 WARNING 模型调用失败，尝试下一个：模型 openai/deepseek-v3.2 调用失败：litellm.APIError: quota exhausted
14:59:11 WARNING 模型调用失败，尝试下一个：...
15:01:43 WARNING 流式模型调用失败，尝试下一个：...
```

**现状**：`router.complete()` 对每个 Provider 无超时保护；只有新增的槽位兜底
（`SLOT_LLM_TIMEOUT_MS=8000`）有 `asyncio.wait_for`。主链路 SQL 生成、结论流式生成都裸奔。

**建议做法**：
1. 给 `complete()` 每个 Provider 套 `asyncio.wait_for`，阈值走配置项
   （建议默认 60~90s，需实测正常 P99 后确定，避免误杀本来就慢的合法请求）
2. 连续失败的 Provider 做短期熔断（如 5 分钟内不再尝试），避免每次请求都重走一遍全链路等待
3. `stream_complete()`（结论生成）同样需要处理——流式场景要包住整个 `async for`

**验收**：在配额耗尽状态下，一次问数应在 ~10s 内落到兜底并返回，而不是挂起数分钟。

**注意**：不要夹带在其它改动里做。阈值取舍需要单独评估。

## 2. `_visible_units` 重复实现（P0）

**为什么记下来**：权限逻辑重复实现，两处漂移会绕过缓存的越权防护。

**证据**：`chat_service.py:28` 与 `runtime.py:404` 各写了一份，注释里也承认「保持一致」。

**风险**：`qa_cache.build_key()` 用 `chat_service` 的版本拼缓存键，`sql_validate` 用
`runtime` 的版本做行级过滤。两处一旦不一致，就会出现「按 A 权限缓存、按 B 权限过滤」的越权。

**建议做法**：抽到 `core/deps` 或 `security/` 下单一实现，两边都调用它。

**验收**：两处引用同一函数；权限相关单测保持通过。

## 3. 问数缓存键缺语义层版本（P0）

**为什么记下来**：改了语义层/槽位后旧答案仍在缓存里，表现为「改了但结果没变」，极难排查。

**证据**：`qa_cache.build_key()` 只由「问题 + 数据源 + 数据权限」三元组构成，
不含语义层或槽位版本。本次做 A/B 对照时，改造后那轮有 **26 条**是缓存命中（<500ms），
改造前 0 条——直接污染了对照结果。

**连带发现**：`.env` 里 `QA_CACHE_TTL=3600` 覆盖了代码默认的 300，缓存实际存活 **1 小时**，
上一轮评测会给下一轮"播种"。

**建议做法**：
1. 缓存 value 里存一份语义层指纹（如 `MAX(updated_at)` 摘要或行内容哈希），
   读取时校验，不匹配即视为未命中
2. `sem_metric` / `sem_rule` 补 `updated_at` 字段（当前没有）
3. 评测前必须清缓存；考虑给评测加专用开关或把 TTL 调短
4. 补一个管理端清缓存入口（当前只有改模型时会触发 `qa_cache.clear()`）

**验收**：改一条指标口径后立即重问同一问题，返回新结果而不是旧缓存。

## 4. 评测集补充与加严判据（P1）

**为什么记下来**：现有 100 条对槽位类改动**没有分辨力**，花了 100 次调用却测不出变化。

**证据**：
- 否定用例 **0 条**
- 取值歧义 1 条（#60），判据仅 `min_rows: 1`——按 unit 还是 industry_cat 过滤都能过
- 同维度多值 5 条，判据仅 `min_rows`/`max_rows`，无法区分筛选条件对错
- **100 条全是单轮**，而槽位真正起作用的是多轮

**建议做法**：
1. 补三类用例：否定（不含/除了/排除…）、多轮追问、取值歧义
2. 加严判据：#60 这类应校验 SQL 里的过滤维度与取值，而不是只看行数
3. 验证槽位改动优先跑 `make check-multiturn`（5 轮，成本低）而非 100 条单轮
4. 配额有限时用 `make check-slots`（零调用）+ 离线回放 diff 替代

**验收**：新增用例在改造前代码上应失败、改造后通过（具备分辨力）。

## 5. 阶段 2：向量召回层（P1）

基础设施已预留（`EMBEDDING_MODEL=bge-m3` 已配置、`sem_fewshot.embedding BYTEA` 已有字段），
缺 embedding 客户端与索引维护。

**价值**：本地模型 10~30ms，比 LLM 快两个数量级、零成本、结果确定。
**边界**：只解决「选哪个」，解决不了否定/区间/多值/比较。定位是阶段 1 前面的廉价召回层：

```
字面命中（0ms）→ 向量召回（~20ms）→ LLM 兜底（~500ms）
```

详见 `docs/11` §4。

  | 模型 | P50 | P90 | 最难用例 | 建议阈值 |
