# 经管之星 · 演示脚本

> 本文对应 I6 的 T6-6。按「先惊艳、再可信、最后可控」的顺序组织，
> 全程约 20 分钟。演示前请先跑一次 `make warmup-cache`，否则首轮提问要等 10 秒以上。

## 演示前准备（2 分钟，别在观众面前做）

```bash
make status                 # 确认 Postgres / Redis / 后端 / 前端都活着
make warmup-cache           # 预热常见问题（P95 24s → 0.1s）
```

浏览器打开 http://127.0.0.1:5181，**隐身窗口**另开一个准备切换角色。

默认口令统一为 `123456`。

---

## 第一幕：惊艳 —— 一句话问数（5 分钟）

**账号**：`admin`

| 步骤 | 操作 | 话术要点 |
| --- | --- | --- |
| 1 | 登录进入「智能问数」 | "这是给经营分析人员用的对话式问数，用业务语言提问，不用写 SQL。" |
| 2 | 输入「2026年各经营单元收入排名」 | 指着左侧 5 步链路："每一步都透明——选了哪些表、怎么推理、SQL 是什么、结果如何、结论怎么来的。" |
| 3 | 结果出来后点「换成饼图」 | 注意强调：**没有重新查库**，是结果二次加工（追问耗时约 0 毫秒）。 |
| 4 | 追问「北京代表处今年达成情况」→「它同比呢」 | 演示多轮指代消解："它"指的是北京代表处，条件会自动继承。 |
| 5 | 问「完成率低于60%的预警单元」 | 展示预警类指标。 |
| 6 | 越界问题：「帮我写首诗」 | 会拒答并引导回经营数据——说明**不会臆测**。 |

**必看细节**：点开某次回答的「查看 SQL」，说明 SQL 是服务端强制加了权限过滤后的最终语句。

---

## 第二幕：可信 —— 数据权限是真的（5 分钟）

**切换**：隐身窗口登录 `zhangsan`（普通用户，仅授权上海、浙江）

| 步骤 | 操作 | 话术要点 |
| --- | --- | --- |
| 1 | 对比两侧菜单 | zhangsan 只有 5 个菜单，没有系统管理与语义层管理。 |
| 2 | 同样问「2026年各经营单元收入排名」 | 管理员看到 10 个单元，zhangsan **只有 2 个**，且结论末尾明确写着"已按您的数据权限范围过滤"。 |
| 3 | zhangsan 问「北京代表处今年达成情况」 | 返回空，但**明确告知是权限范围所致**，并建议联系管理员——而不是让用户以为数据不存在。 |
| 4 | 进「数据台账」看 PPL 明细 | zhangsan 看到 1,397 行，北京相关为 0 行。同样的注入逻辑，台账也生效。 |

**这一幕是重点**：很多系统的权限是"前端隐藏菜单"，这里菜单、接口、SQL、台账四层都过滤了。

## 第三幕：可控 —— 运营闭环（5 分钟）

| 步骤 | 操作 | 话术要点 |
| --- | --- | --- |
| 1 | 在 zhangsan 侧对某个回答点「数据有误」，填说明提交 | 生成反馈单，进入管理员的待办。 |
| 2 | 切回 admin →「反馈管理 ▸ 回复校对」 | 看到那条待处理记录，含**问题原文 + AI 回答快照 + 会话 ID**。 |
| 3 | 点「处理」，填备注，标记已处理 | 状态实时变更，且能一键跳回原会话回放。 |
| 4 | 「系统管理 ▸ 问数日志」 | 会话维度的日志，可按时间/用户筛选，点开是完整对话回放。 |

---

## 第四幕：可配置 —— 不是硬编码（3 分钟）

| 步骤 | 操作 | 话术要点 |
| --- | --- | --- |
| 1 | 「系统管理 ▸ 应用配置」 | 6 张卡片：登录方式、验证码、失败锁定、数据时效、语音开关、开场白与常问阈值。**改完即时生效，不用重启**。 |
| 2 | 「系统管理 ▸ 模型配置」 | 模型的增删改、测试连接、设默认。密钥加密存储，列表只回显脱敏串。切默认模型会自动清缓存。 |
| 3 | 「语义层管理 ▸ 口径规则」 | 口径是写给人看的（如"收入=合同金额按落地月确认"），会拼进 Prompt 约束模型。 |
| 4 | 「语义层管理 ▸ Few-shot」 | 点「验证」会真跑一遍样本 SQL——表结构变更后能立刻发现失效样本。 |

---

## 第五幕：台账导入导出（2 分钟）

| 步骤 | 操作 | 话术要点 |
| --- | --- | --- |
| 1 | 「数据台账」任一页 → 导出 Excel | 服务端生成，数值是真数字（可直接求和），中文文件名正常。 |
| 2 | 用导出的文件当模板改几行 → 点「导入」 | 表头用中文列名，编码列可直接填"上海代表处"这种名称，会自动转成编码。 |
| 3 | 故意把某行填成非法值再导一次 | 会**整批拒绝并回滚**，错误精确到第几行哪个字段——演示"批量写库的谨慎"。 |

## 演示中要主动说明的三件事

诚实说明反而加分：

1. **数据是造的**：6.2 万行按"先定目标、再反推收入"生成，保证目标→收入→完成率自洽，
   并刻意在江西/辽宁/山西留了低达成与同比下滑的样本供分析。
2. **P95 靠缓存达标**：冷启动约 24s（大模型往返），预热后 0.1s。
   真实生产环境应配合更激进的缓存策略与更小的模型。
3. **语音是浏览器原生能力**：Chrome 上中文识别质量够用；服务端 Whisper/TTS 接口已预留，
   未配置时返回 501 而不是静默降级。

## 翻车预案

| 情况 | 处理 |
| --- | --- |
| 提问转圈很久 | 大概率没预热缓存。切到已预热过的问题，或现场跑 `make warmup-cache`。 |
| 模型返回异常 | 系统会自动降级到备用模型，回答里会标注"（降级）"——顺势讲降级链设计。 |
| 切了默认模型后回答风格变了 | 正常，切模型会自动清缓存。 |
| 语音按钮点了没反应 | 只在 Chrome/Edge 支持；Firefox 不支持 Web Speech API。 |
